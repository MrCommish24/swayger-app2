# Swayger User Education and Entry-Journey Assessment

Review the current Swayger codebase and produce a focused UX assessment for how new users learn the difference between:

1. Swayger Game Day Rooms
2. My Swaygers, the 1v1 challenge experience

This is a planning and inspection exercise only.

Do not write or modify code.

Do not:

- Edit files
- Create components
- Change copy
- Change navigation
- Change authentication
- Change routes
- Change database logic
- Add analytics
- Add onboarding
- Deploy
- Commit changes

The goal is to inspect the current experience, show us exactly what new users see today, and recommend the smallest improvements needed to educate users based on how they entered the app.

---

# Background

Swayger now has two related product experiences.

## Game Day Rooms

Game Day Rooms are group experiences built around a live sporting event.

A participant can:

- Open a shared room link
- Join as a guest or authenticated user
- Make pregame picks
- Return for halftime picks
- Return for fourth-quarter or clutch picks
- Follow the leaderboard
- View final standings and receipts

Game Day is now the primary app landing experience.

## My Swaygers

My Swaygers is the existing 1v1 product.

A user can:

- Create a sports take
- Invite a specific opponent
- Join through a code, QR code, or invitation link
- Accept or respond to the challenge
- Lock Swayger Points
- Settle the result
- View the receipt
- View active, pending, settling, and historical Swaygers
- Review leaderboard history and category results

The full 1v1 experience must remain unchanged.

---

# Core product principle

Do not teach every user both products before they can participate.

The entry point should determine what the user learns first.

The likely user journeys are:

## Journey A: User arrives through a Game Day Room link

Preferred flow:

Open link → See room context → Join → Make picks → See leaderboard

The user should not be interrupted with 1v1 education before joining the room.

1v1 may be introduced later as a secondary discovery opportunity.

## Journey B: User arrives through a 1v1 invitation

Preferred flow:

Open invitation → See the take and stake → Join or respond → Complete the Swayger

The user should not be interrupted with Game Day education before responding to the invitation.

Game Day may be introduced later as a secondary discovery opportunity.

## Journey C: User opens the app without an invitation

Preferred flow:

Open app → Land on Game Day home → Understand what Game Day is → See live room, upcoming opportunity, or empty state → Discover My Swaygers as the secondary option

This journey requires slightly more product education because there is no invitation providing context.

# Step 7: Recommend progressive education

Develop a simple progressive-education model.

For each journey, specify:

| Entry Journey | What User Came To Do | What They Need To Learn First | What Should Not Interrupt Them | Best Time to Introduce the Other Product |

Cover:

- Game Day link
- 1v1 invite link
- App opened without invitation
- Existing Game Day participant returning later
- Existing 1v1 user opening the app
- Completely new account with no activity

The recommendation should follow this principle:

> Teach users only what they need for the next action, then reveal the rest after they participate.
