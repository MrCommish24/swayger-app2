PRODUCT DECISIONS

1. PICK DEADLINE MUST AUTOMATICALLY CLOSE SUBMISSIONS

We should NOT rely only on the commissioner manually locking the card.

The existing pick_deadline must become a server-enforced write cutoff.

Behavior:

Before pick_deadline:
- participant can submit picks
- participant can edit existing picks
- participant can update selections

At or after pick_deadline:
- backend rejects new picks
- backend rejects edits/updates
- existing picks remain readable
- no scheduler/cron is required
- enforcement should happen server-side on every write

The server is authoritative.

Do not rely only on frontend disabling.

Use the existing room pick_deadline value.

2. COMMISSIONER LOCK IS NOW A REVEAL/FREEZE MOMENT

Do not remove the existing commissioner lock flow.

But conceptually separate:

pick_deadline = submissions/edits automatically close

commissioner lock = commissioner confirms/reveals the competition state / receipts

For V1:
- deadline closes editing automatically
- commissioner can lock after the deadline
- lock remains manual
- no auto-lock scheduler
- no cron job

If the existing lock endpoint already blocks further picks, preserve that too.

Deadline OR card lock should prevent writes.

3. COPY / STATE LANGUAGE

Update Madden participant UI language to reflect this distinction.

Before deadline and before card lock:
- user can edit picks

Preferred confirmation copy:
“Picks confirmed. You can update until the deadline.”

At/after deadline but before commissioner lock:
Preferred state/copy:
“Picks are closed. Waiting for the commissioner to reveal receipts.”

After card lock:
Use the existing locked/reveal state as appropriate.

Do not use language that implies picks are permanently locked when they are still editable.

4. BACK BUTTON

The current Back control on the Madden/Game Day participant page does not work correctly.

Fix it.

For V1:
- Back should route to /gameday
- label can remain “Back” or become “Game Day” if that is more consistent with the existing design
- do not attempt a Discord deep link
- do not build a guest dashboard in this task

For authenticated users:
- /gameday should behave as the existing Game Day Hub

For guest users:
- /gameday should load safely and not error
- if current signed-out Game Day behavior already has a landing/promo state, reuse it
- do not require signup just to leave the room
