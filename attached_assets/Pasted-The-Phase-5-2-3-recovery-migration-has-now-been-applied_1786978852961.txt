3. REQUIRED SECURITY OUTCOME
==================================================

Desired architecture:

Normal clients must NOT be able to directly:

- SELECT recovery token rows
- enumerate member recovery requests
- INSERT arbitrary recovery token records
- UPDATE token status
- mark tokens redeemed/revoked
- DELETE token records

All sensitive operations should occur through:

- authorized server routes
and/or
- narrowly-scoped SECURITY DEFINER RPCs

The fact that token_hash is not the raw token is NOT sufficient reason to permit direct table CRUD.
