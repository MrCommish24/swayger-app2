This phase has only two goals:

2. add a focused browser E2E test for Sign In → return to Week N

==================================================
1. PRODUCT PRINCIPLE
==================================================

Guest access remains important.

We do NOT want to require account creation before someone can participate.

The low-friction flow stays:

Join as guest
→ immediately participate

But after the guest is successfully in the league, Swayger should clearly explain:

Guest access is tied to this browser/device.

Connecting an account protects their league spot across devices and future weeks.

This should be an optional upgrade, not a gate.

==================================================
2. INSPECT CURRENT GUEST-UPGRADE UX
==================================================

Before changing code, inspect every place we currently offer:

- Create Account
- Sign In
- guest → authenticated claim upgrade
- “You’re in!” guest success screen
- Fantasy League Hub guest state
- Draft Day guest join success
- weekly guest join success

Report where the current upgrade prompt appears and what it says.

Reuse the existing guest→account upgrade infrastructure.

Do NOT create another claim-transfer mechanism.

==================================================
3. PRIMARY POST-JOIN NUDGE
==================================================

Immediately after a guest successfully claims a Fantasy league seat, strengthen the existing upgrade prompt.

Preferred copy:

Keep your league spot on any device

You’re in as a guest. Your league access is currently saved to this browser/device.

Connect a Swayger account so you can return to your Draft Day and weekly Swaygers even if you switch devices or clear your browser.

Primary CTA:

Save My Spot

Secondary:

Maybe Later

If “Save My Spot” is too ambiguous relative to existing auth language, use:

Create Account / Sign In

but preserve the benefit-focused headline and explanation.

Do NOT use alarming language.

Do NOT imply their current guest access is broken.

==================================================
4. RETURN TARGET MUST BE PRESERVED
==================================================

If guest taps the upgrade CTA from:

- Draft Day
- Week 1
- Week 2
- future Week N

return to the exact week/play/hub route they came from.

Use the auth return URL mechanism that Phase 5.2.1 fixed.

Do not dump them on the general app home page.

==================================================
5. WEEKLY HUB NUDGE FOR DEVICE-ONLY GUEST
==================================================

For an existing guest who has NOT connected an account:

consider a small non-blocking banner on the Fantasy League Hub.

Preferred:

🔐 Keep your league access

You’re playing as a guest on this device. Connect an account to keep your spot if you switch devices.

[ Save My Spot ]

The banner should:

- appear only to the current viewer if they are a device-only guest
- NOT appear to authenticated members
- NOT appear to commissioners merely because other people are guests
- be dismissible if easy using existing local UI state
- not dominate the page

Do not add a new database preference just to remember dismissal.

If persistent dismissal would require schema work, omit persistence for V1.
