CURRENT CONCERN

The current hub auto-upgrade behavior fires whenever:

- an authenticated session exists
- a Fantasy guest token exists

That is too broad.

On a shared browser/device, Guest A may have claimed a Fantasy seat, then User B could later sign in. We must not silently transfer Guest A's league seat merely because an authenticated session appeared on a device containing the old guest token.

DESIRED BEHAVIOR

Guest → authenticated conversion should be tied to explicit upgrade intent.

Preferred journey:

Guest claims:
Mike — Sunday Scaries

→ success screen

“You’re in!”

→ guest taps:

Create Account / Sign In
“Keep your league across devices”

→ system records a pending Fantasy claim-upgrade context

→ user authenticates

→ after successful authentication, ONLY that intended guest claim is upgraded to the authenticated user

→ user returns to Food Pyramid as Mike

Do not require account creation. “Open My League” and continued guest use remain available.

IMPLEMENTATION PRINCIPLES

1. Do not trigger claim ownership transfer solely because session != null and a guest token exists.

2. Tie upgrade to an explicit pending-upgrade state created when the user chooses Create Account / Sign In from the guest claim experience.

3. Prefer upgrading a specific claim/league_member rather than every row sharing a guest token, unless you can demonstrate that guest_token is intentionally one-person identity across all Fantasy leagues and that upgrading all claims is the desired product behavior.

4. Server must validate that:
   - the target active claim is currently a guest claim
   - the provided guest token matches that claim
   - the requested claim/league_member is the one being upgraded
   - it is not already owned by a different authenticated user
   - the UPDATE changes the existing row rather than creating a second active claim

5. Same-account/retry behavior should remain idempotent.

6. A normal unrelated sign-in on a device with an old Fantasy guest token must NOT transfer a seat automatically.
