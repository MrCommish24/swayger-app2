## File 2: app/(tabs)/index.tsx

Inside the My Swaygers card shown on the Game Day empty state, update the copy for an authenticated user whose Swaygers query has successfully resolved to an empty array.

“Create, join, and manage your 1v1 Swaygers while you wait for the next Game Day Room.”

With:

“Challenge a friend to a 1v1 sports prediction.”

Keep the existing CTA:

“View My Swaygers →”

Keep its route:

`/(tabs)/challenges`

### Loading-state requirement

Do not treat loading as the same as zero Swaygers.

The new zero-Swayger copy should display only when:

- The user is authenticated
- The Swaygers query has completed successfully
- The returned Swaygers array is empty

While loading, preserve the current loading or static fallback behavior without briefly showing “zero Swaygers.”

For users with existing Swaygers, keep the current dynamic display unchanged:

- Active count
- Swayger Points balance
- View My Swaygers CTA

For unauthenticated users, preserve the existing static fallback behavior unless the current implementation already uses the same educational copy safely.

1. A zero-Swayger user sees a clear one-sentence definition of a 1v1 Swayger.
2. The user sees the basic sequence: make a take, opponent counters, both lock it in, settle after the game.
3. The existing tutorial example remains unchanged.
4. Create Your First Swayger routes to `/(tabs)/create`.
5. Join with a Code routes to `/join`.
6. Existing users with Swaygers still see all history, filters, activity, and StatsStrip unchanged.
7. The Game Day home shows “Challenge a friend to a 1v1 sports prediction” only after the Swaygers query confirms the user has zero Swaygers.
8. Existing users continue seeing active count and SP balance.
9. No backend, database, authentication, settlement, points, or Game Day logic changes.
10. The layout works on mobile web, native mobile, and desktop web.
