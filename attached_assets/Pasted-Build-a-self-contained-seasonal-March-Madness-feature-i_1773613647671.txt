Product framing:
- seasonal March Madness module
- private pools only
- bragging rights only
- no real money
- no gambling
- easy to share

==================================================
VERY IMPORTANT: DATA-DRIVEN BRACKET
==================================================

The bracket UI must be fully data-driven.

Do NOT hardcode the bracket layout or hardcode matchups directly in the UI.

Instead, build an internal bracket model that supports:
- round
- region
- bracket_location or slot_position
- home_team_id
- away_team_id
- winner_team_id
- next_game_id

The UI should render rounds dynamically from the internal bracket data.

User picks should be stored against bracket_game_id (or equivalent internal game/node id), not against a fragile hardcoded UI structure.

Store bracket relationships using next_game_id so winners can automatically populate the correct matchup in the next round.

The system must work whether the structure comes from:
1. BallDontLie bracket data
2. manual imported bracket data

==================================================
SCORING RULES
==================================================

Use standard scoring:

- Round of 64 = 1
- Round of 32 = 2
- Sweet 16 = 4
- Elite 8 = 8
- Final Four = 16
- Championship = 32

Tiebreaker:
- predicted championship game total points

Scoring engine requirements:
- score when games become final
- idempotent rescoring
- able to rescore one game, one pool, one entry, or all entries
- no double counting
- always recomputable from current game results

==================================================
LOCKING RULES
==================================================

Bracket entries lock at tournament start.
Default:
- lock all entries at the start of the first tournament game

After lock:
- users cannot edit picks
- users cannot edit entry names if that impacts integrity
- admin can still correct feed/data issues
