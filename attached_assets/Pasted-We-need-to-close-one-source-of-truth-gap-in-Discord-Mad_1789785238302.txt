We need to close one source-of-truth gap in Discord Madden Pick Card Win Conditions.

CONTEXT

The Discord bot now supports two commissioner-selected Win Conditions:

1. perfect_card
2. most_correct

Perfect Card maps naturally to the existing backend:

scoring_mode = "all_correct"

However, Claude found that no backend scoring_mode value currently exists or is documented for Most Correct.

The Discord bot can calculate Most Correct winners from the backend's existing:

- correct_picks
- total_picks

but we do NOT want Discord to be the only place that knows the card's winner semantics.

The backend/web experience must agree with Discord.

GOAL

Add first-class backend support for:

scoring_mode = "most_correct"

for Discord Madden Weekly Pick Cards.

Do not change Perfect Card behavior.

==================================================
SCORING MODES
==================================================

Support:

all_correct
most_correct

Semantics:

ALL_CORRECT

Winner(s) are participants where:

correct_picks === total_picks

If nobody is perfect:
- no winner

Multiple perfect participants:
- tied winners

MOST_CORRECT

Winner(s) are participant(s) with the highest correct_picks count after all required props are settled.

Example:

Darius 2/3
Mike 1/3
Chris 1/3

Winner = Darius

Tie:

Darius 2/3
Mike 2/3
Chris 1/3

Winners = Darius + Mike

Do not add a tiebreaker.

==================================================
CREATION CONTRACT
==================================================

Discord bot should be allowed to send:

Perfect Card:

format_config.scoring_mode = "all_correct"

Most Correct:

format_config.scoring_mode = "most_correct"

Inspect the current request validator.

Update validation narrowly so both values are accepted.

Do not loosen scoring_mode to arbitrary strings.

Legacy cards with:

all_correct

remain unchanged.

Cards without a scoring mode should preserve the current legacy/default behavior.

==================================================
FINAL STANDINGS
==================================================

The backend final standings response must determine winner semantics using scoring_mode.

Do not make Discord independently authoritative.

Expose enough information in final standings for clients to know:

- scoring_mode
- correct_picks
- total_picks
- winner / winning participant IDs or equivalent existing winner indicator
- tie state if existing response shape supports it

Prefer adapting the existing final-standings response rather than creating a second endpoint.

For all_correct:

2/3 must never be declared winner simply because it is the highest score.

For most_correct:

2/3 may be winner when it is the highest score.
