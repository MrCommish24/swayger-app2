Swayger Fantasy Draft Day — Build Assessment & SOP Request

You are working inside the existing Swayger application.

Before making any code changes, I want you to inspect the current application and produce a detailed implementation assessment and recommended SOP for adding a new Swayger Fantasy Draft Day experience.

Product context

Swayger is currently centered around sports prediction experiences, particularly Game Day Rooms.

The existing Game Day Room flow includes concepts such as:

- Room creation
- Join-by-link / invite flow
- Multiple participants
- Prediction / prop questions
- Answer options
- Pick locking
- Host/admin settlement
- Scoring
- Leaderboards
- Final standings / results
- Shareable results
- Existing Game Day room infrastructure and data models

We want to determine how much of this existing architecture can be reused for a new fantasy-football-specific experience.

Do not assume we need a completely separate application or architecture.

The preferred approach is to extend or adapt what already exists wherever practical.

---

Objective of this assessment

We want to launch an MVP called:

Swayger Fantasy Draft Day

The purpose of the MVP is to validate one question:

Does Swayger make a fantasy football draft more fun and engaging for the members of an existing fantasy league?

This is specifically a Draft Day validation product, not yet a complete season-long fantasy product.

Do not begin implementation.

First inspect the codebase and tell me exactly what would be required.

---

MVP scope

The first version should include:

1. Fantasy league setup

A host/commissioner should be able to create a fantasy league experience.

At minimum, determine what would be necessary to support:

- Fantasy league name
- Commissioner / host
- List of league members
- Approximately 8–14 league members
- Persistent league identity so the Draft Day Room belongs to that fantasy league

We need your recommendation on whether this should:

A. introduce a new "fantasy_leagues" concept/table,

B. reuse or extend the existing Game Day room model,

C. use another existing entity already in the application,

or

D. use some hybrid approach.

Do not automatically create a new model if the existing structure can handle this cleanly.

---

2. Draft Day room

The commissioner should be able to create or launch a Draft Day Swayger for that fantasy league.

League members should be able to join through the simplest version of the existing Game Day join experience.

Reuse existing link-sharing, guest/user joining, room membership, or similar infrastructure wherever appropriate.

The Draft Day Room should support props such as:

- Who will get the first draft position?
- Who will get the last draft position?
- Which player will be selected first overall?
- Which league member will draft the first quarterback?
- Which league member will draft the first defense?
- Who will draft the first rookie?
- Who will make the biggest reach?
- Who will have the best draft?

These examples are illustrative. We do not need all of them hard-coded.

---

3. Fantasy-specific answer options

One important difference from normal Game Day Rooms is that some answers should be league members.

For example:

Who will draft the first QB?

Answers:

- Darius
- Chris
- Mike
- Anthony
- etc.

Other props may have standard text or player-name answers.

Assess how the existing "answer_options" architecture works today and whether league-member answer choices can already be represented without structural changes.

Identify any limitations.

---

4. Prop templates

We should not require the commissioner to manually type every Draft Day question.

Assess the cleanest way to support a small library of reusable:

Fantasy Draft Day Prop Templates

For example:

- Draft position props
- Player drafted first props
- Position drafted first props
- League-member behavior props
- Post-draft opinion props

Determine whether the existing Game Day "template_prop_id" or related template infrastructure can support this.

Reuse the existing template system wherever possible.

Do not build a sophisticated automated prop-generation engine in this MVP.

---

5. Picks and locking

League members should make predictions before the applicable prop locks.

Assess whether the existing Game Day pick lifecycle can be reused unchanged.

Identify:

- Current pick model
- Existing lock mechanism
- Whether room-level or prop-level locking exists
- Any changes needed for Draft Day

Prefer minimal changes.

---

6. Settlement

For the MVP, the commissioner/host can manually settle props.

Example:

Who drafted the first QB?

Commissioner selects:

Mike

Existing scoring should then update.

Assess whether the current Game Day settlement system can support this directly.

We recently worked on settlement architecture, including per-room settlement and broader global settlement capabilities. Do not redesign settlement unnecessarily.

Determine what can be reused.

---

7. Draft Day leaderboard

Participants should receive points based on correct predictions.

For the MVP, keep scoring simple.

We do not need:

- advanced wagering
- complex multipliers
- confidence points
- monetary payouts
- wallet functionality
- prize accounting

Assess whether existing Swayger Points or Game Day scoring can simply be reused.

Recommend the minimum viable scoring method.

At the end of Draft Day, participants should see a final leaderboard / Draft Day winner.

---

8. Draft Day completion

The final experience should clearly indicate:

- Draft Day Swayger is complete
- Final standings
- Draft Day winner
- Individual correct picks / results where already supported
- Existing share functionality if it can be reused easily

Do not create a broader season-long experience yet.

---

Explicitly OUT OF SCOPE

Do not include these in the MVP implementation plan unless a foundational data decision now would prevent us from adding them later.

Out of scope:

- Season-long weekly Swayger competitions
- Week 1–17 fantasy rooms
- Season-long fantasy leaderboard
- Fantasy playoff competitions
- Prize pool accounting
- Prize distribution
- Payout tracking
- Leagueswype integration
- ESPN integration
- Yahoo Fantasy integration
- Sleeper integration
- NFL Fantasy integration
- Automatic roster syncing
- Automatic fantasy scoring imports
- Automated result settlement through fantasy APIs
- Payment processing
- Betting functionality
- Commissioner financial tools

We may build some of these later.

The MVP should not become dependent on them.

---

Important product principle

Do not build a fantasy football platform.

The user's existing fantasy league still lives on ESPN, Yahoo, Sleeper, NFL Fantasy, etc.

Swayger is an engagement and prediction layer around the league, beginning with Draft Day.
