# PHASE 5.2.1 — GUEST RETURN / RECOVERY UX

CURRENT SCENARIO

A league member originally joined Draft Day as a guest using an incognito/private browser.

That created:

- a persistent fantasy_member_claim in the database
- tied to a durable guest_token stored in that browser/device

Later, the incognito session was closed.

The database still knows the seat is claimed, but the new incognito session no longer has the old guest token.

Then:

1. Commissioner shares Week 1 direct link.
2. Returning guest opens it in a new incognito window.
3. Weekly play screen says:

“You’re not part of this league”

4. “Back” button does nothing.
5. “Join This League” sends them to the league join page.
6. Join page says:

“All seats in this league have been claimed.”

This is technically consistent with the current guest-token architecture, but the UX becomes a dead end.

We need to fix the dead end without weakening identity security.

Do NOT begin Week 3 or any unrelated feature work.

==================================================
1. INSPECT THE CURRENT GUEST IDENTITY FLOW FIRST
==================================================

Trace:

- fantasy_member_claims
- guest_token creation/storage
- guest-token lookup
- guest → authenticated upgrade
- league join route
- weekly play non-member route
- shared Week link routing
- current “all seats claimed” logic

Return exact current behavior for:

A. same-device returning guest
B. different-device/new-browser returning guest
C. guest whose browser storage was cleared
D. authenticated user with an existing claim
E. authenticated user with no claim

Confirm whether a guest claim is currently recoverable by any mechanism other than presenting the original guest token.

Do not infer.

==================================================
2. DO NOT EMBED MEMBER IDENTITY IN WEEK LINKS
==================================================

Preserve the security rule:

The shared Week link identifies:

- league
- season
- week

It must NOT identify:

- member
- seat
- guest token
- auth user
- fantasy team

Do not “fix” this by putting a guest token or season_member_id into the shared URL.

==================================================
3. FIX THE BROKEN BACK BUTTON
==================================================

The “← Back” button on the weekly non-member screen currently does nothing.

Fix it.

Do not rely on router.back() if navigation history may be empty or unstable.

Preferred deterministic destination:

the Fantasy League Hub for:

/fantasy/:leagueId/:seasonId

Use the actual canonical route.

If the user cannot access the hub because they are not a member, route instead to the safest existing league landing/join screen.

The button must never be inert.

==================================================

Replace with something more useful:

Actions:

Do not imply they definitely need to join again.

If auth state already exists, hide Sign In appropriately.

Actions:

7. UNUPGRADED GUEST — CURRENT LIMITATION
==================================================

For a guest who NEVER connected an account and loses the original guest token:

do not silently reclaim the seat.

That would allow identity takeover.

For this phase, if no safe recovery credential exists:

show a clear limitation.

Example:

“Guest access is tied to the browser/device you originally used. If you no longer have access to that device, ask your commissioner for help.”

Do NOT invent insecure seat recovery.

==================================================
9. DO NOT RESET CLAIMS AUTOMATICALLY
==================================================

Never do:

- clear guest claim because token is missing
- free the seat automatically
- create duplicate member
- overwrite claim with a new guest token
- let a forwarded link reclaim an occupied seat

All of those create identity/security problems.

13. JOIN RETURN TARGET
==================================================

Do not route them into an ineligible play screen.
