# 2. Fix Game Day host JWT verification

This is the first required change.

The current host authentication must not trust an unverified JWT payload.

Replace the current decode-only authentication path with **verified Supabase authentication**.

Use the project's existing verified caller/auth pattern if one already exists, such as `getCallerIdentity()` or equivalent.

Requirements:

* Extract the bearer token from the request.
* Verify the token using Supabase Auth.
* Do not trust locally decoded email/user claims before verification.
* Reject:

  * malformed tokens
  * unsigned/fabricated JWT-shaped strings
  * expired tokens
  * tokens Supabase does not recognize
* Obtain `user.id` and email only from the verified Supabase Auth response.
* Apply `GAMEDAY_HOST_EMAILS` / host allowlist only **after** token verification.
* Preserve the existing intended host/admin authorization behavior wherever possible.

Do not expose secret values.

Do not weaken authentication for any existing route.

## Required negative tests

Add tests proving that:

* a fabricated JWT-shaped token with an allowlisted email is rejected
* an invalid bearer token is rejected
* a valid authenticated user who is not an allowed Game Day host is rejected where host authorization is required
* a valid authenticated allowed host is accepted

If the repo has no existing test framework for these route handlers, use the smallest maintainable test approach already compatible with the project.

Do not introduce a large testing framework migration solely for this task.

# 3. Add a guild-bound Discord operator authorization model

We need an explicit backend authorization boundary for operations initiated by the Swayger Discord bot.

For Discord operator requests, the intended contract should be:

1. Valid shared `GAMEDAY_BOT_API_KEY`
2. Requesting `discord_guild_id`
3. Room reference / room ID / card or prop that resolves to a room
4. Backend verifies:

`room.discord_guild_id === requestingDiscordGuildId`

The shared API key authenticates the **Swayger bot service**.

The guild ID authorizes the **specific Discord server** to operate the room.

The shared API key alone must never imply access to all Discord rooms.

# 4. Create a reusable Discord Game Day authorization helper

Do not duplicate the same authorization logic across many routes.

Create a small reusable helper appropriate to the current codebase that can:

* validate the bot API key
* read the requesting Discord guild ID
* load/resolve the relevant Game Day room
* confirm the room is a Discord-owned room where appropriate
* confirm the stored `discord_guild_id` exists
* compare stored guild ID to requesting guild ID
* reject mismatches

Use clear status codes.

Recommended behavior:

### 401 Unauthorized

Use when:

* bot API key missing
* bot API key invalid

### 400 Bad Request

Use when:

* a Discord operator request is missing required `discord_guild_id`

### 403 Forbidden

Use when:

* room has a different `discord_guild_id`
* the caller is authenticated as the bot but is not authorized for that room

### 404 Not Found

Preserve existing room-not-found behavior where appropriate.

Avoid returning unnecessary details that help enumerate other guilds' rooms.
