# SWAYGER RUN — PREMIUM WEEKLY PLAY UX + MY LOCK
## ARCHITECTURE / IMPLEMENTATION ASSESSMENT ONLY

Do NOT implement the feature yet.

We are happy with the current Swayger Fantasy Weekly product and the newly launched:

- named Swayger Moments
- Call Your Shot / Share My Pick
- Weekly autosave
- guest/auth identity
- League Picks
- settlement
- Weekly Results
- Weekly Receipt

We want to explore a low-cost UX upgrade that makes making Weekly picks feel less like filling out a form and more like completing a short Swayger game session.

The product concept is:

THE SWAYGER RUN

One Moment at a time.
Every call gets acknowledged.
Progress builds visibly.
Completion gets a payoff.
The participant chooses one prediction as MY LOCK.
MY LOCK naturally feeds into Call Your Shot.

This is primarily a UX/presentation enhancement.

It must NOT become:

- a new scoring system
- an XP economy
- a streak system
- a coin/reward system
- an avatar system
- a social feed
- a complicated animation project
- a custom gesture/dial control
- a rewrite of Weekly Fantasy architecture

Product north star:

LESS LIKE FILLING OUT PICKS.
MORE LIKE PUTTING YOUR TAKES ON THE RECORD.

==================================================
3. ONE-CARD FOCUS MODE
==================================================

Assess a focused one-card-at-a-time experience.

Requirements:

- one Moment receives primary visual focus
- user still retains ability to go backward
- previously saved picks remain editable before lock
- no answer is lost when navigating between Moments
- user may leave and return
- existing picks should restore correctly
- question count must be fully dynamic

It must work equally well for:

- 3 questions
- 5 questions
- 7 questions
- 12 questions
- any future supported count

Do NOT design around exactly five questions.

Assess:

- next/back behavior
- whether auto-advance after successful save is desirable and safe
- whether a brief acknowledgement state should appear before advancing
- whether swipe navigation is necessary

Strong preference:

Do NOT add swipe gestures in V1 unless already trivial.

Buttons/taps are sufficient.

5. PICK ACKNOWLEDGEMENT MICROINTERACTION
==================================================

After the server confirms a saved answer, we want a brief premium-feeling acknowledgment.

Possible controlled phrases:

- ON THE RECORD
- CALL MADE
- YOU'RE STANDING ON IT
- RECEIPT PENDING 👀

Do not create an elaborate randomized content engine.

Assess a small deterministic or lightly rotating phrase bank.

Important:

The acknowledgment must happen only after the current answer is successfully saved.

Do not celebrate an optimistic answer that later fails to persist.

Assess a lightweight visual treatment such as:

- answer becomes more prominent
- card contracts slightly
- checkmark appears
- small scale/fade transition
- progress meter advances

Avoid heavy animation.

Respect reduced-motion preferences.

==================================================

We want to assess a simple confidence mechanic.

Product name:

MY LOCK

Completion prompt:

- change correctness

It is:

- confidence
- identity
- expression
- sharing

Assess how best to represent and persist one selected lock per participant per Weekly competition.

FIRST inspect whether the existing schema can support this safely.

Possible conceptual models may include:

- participant-level reference to selected prop
- metadata
- another existing relationship

Do NOT choose or implement a schema yet.

If persistence requires a schema change, document:

- smallest additive model
- uniqueness rule
- delete/update behavior
- guest/auth compatibility
- archive behavior

Do not write migration yet.

11. RESUME / RETURN EXPERIENCE
==================================================

This is important.

Assess what happens when a user:

- completes 2 of 5 and leaves
- completes 4 of 7 and leaves
- returns later
- already completed every pick
- already selected My Lock
- changes a previous answer
- changes the answer that was My Lock

Recommended conceptual behavior:

Incomplete user:
resume at first unanswered Moment.

Completed user:
open into completion summary / current Swayger state.

If the answer attached to My Lock changes:
My Lock remains attached to that Moment, unless there is a technical/product reason it should reset.

Assess and recommend.
