2. FIX PL/PGSQL ROW_COUNT HANDLING

The proposed syntax:

GET DIAGNOSTICS v_participant_upd = (ROW_COUNT > 0);

is invalid.

Use an integer variable, e.g.:

v_participant_rows INT := 0;

UPDATE ...;

GET DIAGNOSTICS v_participant_rows = ROW_COUNT;

v_participant_upd := v_participant_rows > 0;

Audit the complete RPC for valid PostgreSQL/PLpgSQL syntax before returning migration SQL.

4. MAKE LATE "ADD TO LEAGUE ONLY" ATOMIC

Current proposal:

add_fantasy_season_participant
→ creates draft_day_eligible=true
→ separate UPDATE flips it false

Do not use this two-step state transition.

The user action:

"Add to League Only"

must atomically create the member/season member/team/team-manager with:

draft_day_eligible=false

when Draft Day has already received picks.

Prefer extending the existing participant RPC with an explicit parameter such as:

p_draft_day_eligible BOOLEAN DEFAULT TRUE

or create a narrowly-scoped wrapper RPC if changing the existing signature risks regressions.

The backend determines the correct value based on lifecycle.

Do not trust a client-provided eligibility boolean.

Required lifecycle:

no Draft Day
→ eligible=true

published + pick_count=0
→ eligible=true
→ update published answer universe atomically

pick_count>0
→ eligible=false
→ current Draft Day untouched

locked
→ eligible=false
→ current Draft Day untouched

There must never be a committed intermediate state where a late League-Only member is temporarily Draft Day eligible.

5. CONSIDER MAKING ADD + SNAPSHOT UPDATE ATOMIC TOO

When pick_count=0 and Draft Day is already published:

Add member
+
update published answer_options

is one logical commissioner operation.

Do not:

commit new league member
→ separately mutate Draft Day answer options

If the second operation fails, the league roster and published Draft Day universe become inconsistent.

Use a transactional RPC/wrapper for the post-publish add path if necessary.

The result should be all-or-nothing.
