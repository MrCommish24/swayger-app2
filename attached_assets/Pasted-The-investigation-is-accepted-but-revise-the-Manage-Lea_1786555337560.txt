Three product/architecture corrections are required.

1. LATE MEMBER ADDITION AFTER PICKS EXIST

Do NOT simply add a new member to the active league while leaving the existing Draft Day answer universe unchanged and allow that member to participate normally.

That can create an unfair/invalid prop.

Example:

Published prop:
"Who drafts the most RBs?"

Existing answer_options:
Darius
Mike
Rob

Members begin making picks.

Commissioner then adds Chris.

If Chris participates in the draft and ultimately drafts the most RBs, Chris could be the objectively correct answer even though no existing participant was ever allowed to select Chris.

Therefore distinguish:

LEAGUE MEMBERSHIP
from
CURRENT DRAFT DAY ELIGIBILITY.

Recommended lifecycle:

A. BEFORE DRAFT DAY PUBLISH
→ Add normally.
→ Member is eligible for Draft Day.

B. AFTER PUBLISH, GLOBAL pick_count = 0
→ Add normally.
→ Regenerate affected season_member / fantasy_team answer_options for the existing Draft Day snapshot.
→ No reset required because nobody has picked.

C. AFTER GLOBAL pick_count > 0 BUT CARD STILL OPEN

Commissioner must explicitly choose:

OPTION 1:
"Add to League Only"

Result:
- create persistent league member
- create season member/team
- member exists in league
- member is NOT added to the currently-active Draft Day answer universe
- member should not participate in this Draft Day competition if doing so could make them an outcome for existing roster-target props
- they participate in future competitions

OPTION 2:
"Add to Draft Day & Reset Picks"

Result:
- add member
- delete/reset ALL existing Draft Day picks for this card
- regenerate relevant published answer_options using the new roster
- preserve the existing question set
- card remains/open returns to open
- every participant starts Draft Day picks again from zero
- show a strong confirmation explaining that existing picks will be erased

This reset must be explicit. Never silently reset picks.

D. AFTER CARD LOCKED
→ allow "Add to League Only"
→ do not alter current Draft Day
→ do not reset current Draft Day from the Manage Members flow

Do not implement the full reset behavior until you confirm the safest atomic approach.

2. RENAME BEHAVIOR

Stable IDs make display-name/team-name corrections semantically safe.

If:

Mike → Michael

the season_member_id stays identical.

Therefore, while the Draft Day competition is active, prefer updating the DISPLAY LABEL associated with that same stable ID in relevant published answer_options.

Existing gameday_picks.selected_answer values do not change.

Similarly:

The Ballers → Sunday Scaries

fantasy_team_id remains the same.
Update corresponding published answer-option labels when appropriate.

Recommended lifecycle:

Before/fresh Draft Day:
→ update current league name/team name
→ update active Draft Day snapshot labels for the same stable IDs

After picks exist but before settlement:
→ label correction still allowed because IDs do not change
→ do not reset picks

After Draft Day is settled/finalized:
→ preserve historical competition snapshots unless we later build an explicit historical correction mechanism

Also consider updating the current gameday_participant display/team snapshot for an active Draft Day when it is clearly a correction and the stable identity is unchanged.

Do not modify selected_answer IDs.
